# Гибридная СППР по защите посевов

Учебный прототип гибридной интеллектуальной системы принятия решений по защите посевов
на основе нейросетевого распознавания и базы знаний. МГТУ им. Н. Э. Баумана, кафедра ИУ5.

Нейросеть распознаёт болезнь по фото листа, а база знаний на продукционных правилах превращает
диагноз и агрономический контекст (доля поражённых растений, погода, сроки до уборки, прошлая
обработка) в решение — обрабатывать, наблюдать или перепроверить — с цепочкой правил и
коэффициентами уверенности.

## Установка и запуск

Нужен Python 3.11+ (Windows 11, macOS, Linux; только CPU).

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate    macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

При первом запуске модель скачивается с Hugging Face (~25 МБ) и дальше берётся из кэша.
Интернет нужен только для этого и для необязательной погоды из Open-Meteo.

Самопроверка нейросети без интерфейса — печатает `id2label`, метки без записи в базе знаний и
top-3 с временем распознавания для каждого фото из `examples/`:

```bash
python classifier.py
```

## Архитектура

```
фото листа ──► classifier.py (ViT-Tiny, top-3) ──┐
данные о поле / weather.py (Open-Meteo) ─────────┼──► рабочая память (факты + CF)
kb/diseases.json (поля болезни) ─────────────────┘            │
kb/rules.json (20 правил) ──► engine.py: прямой вывод с CF ◄──┘
                                   │
                                   ▼
             решение + д.в. + исключения + цепочка правил ──► app.py (Streamlit)
```

1. `classifier.py` — готовая модель [wambugu71/crop_leaf_diseases_vit](https://huggingface.co/wambugu71/crop_leaf_diseases_vit)
   (ViT-Tiny, 5,5 млн параметров; пшеница, кукуруза, картофель, рис) выдаёт top-3 с вероятностями.
   Настоящий `id2label` — 13 классов: по 3 у пшеницы, картофеля и риса, 3 у кукурузы (ржавчина,
   церкоспороз, здоровый лист) и `Invalid`. Гельминтоспориоза кукурузы, заявленного в карточке, в модели нет.
2. Метки модели нормализуются и сопоставляются с разделом `labels` в `kb/diseases.json`.
3. `app.py` собирает рабочую память: данные пользователя (CF = 1), выход нейросети
   (CF = вероятность top-1), поля болезни из базы знаний.
4. `engine.py` проходит по правилам сверху вниз, пока срабатывает хотя бы одно; CF вывода =
   CF правила × min CF условий, повторные выводы объединяются: CF₁ + CF₂·(1 − CF₁).
5. Интерфейс показывает решение, д.в. с причинами исключения и трассировку сработавших правил.

Вся предметная логика — в JSON; в Python только универсальный движок и интерфейс.

| Файл | Назначение |
|---|---|
| `app.py` | Streamlit-интерфейс: условия на поле, вкладки «Диагностика», «База знаний», «Журнал» |
| `classifier.py` | загрузка модели, top-3, сопоставление меток с базой знаний |
| `engine.py` | машина вывода: факты, правила, CF, трассировка |
| `weather.py` | погода по координатам из Open-Meteo (необязательно) |
| `config.py` | ID модели, пороги уверенности, пути к файлам |
| `kb/diseases.json` | культуры, метки модели, 9 болезней: ЭПВ, условия развития, симптомы, меры |
| `kb/products.json` | 8 действующих веществ: класс, FRAC, срок ожидания, норма |
| `kb/rules.json` | 20 правил ЕСЛИ–ТО с CF и русские подписи решений |
| `examples/` | тестовые фото с источниками и лицензиями (`examples/README.txt`) |
| `evaluate.py` | замер точности моделей и пользы гибрида на открытых снимках |
| `results/` | результаты замеров, список тестовых снимков, скриншоты сценариев |
| `history.csv` | журнал решений, создаётся автоматически |

## Сценарии для демонстрации

| № | Фото | Ввод (остальное — по умолчанию) | Решение |
|---|---|---|---|
| 1 | бурая ржавчина пшеницы | 6 %, 20 °C, 85 %, осадки были, ветер 3 м/с, 40 дней | обработка: тебуконазол, пропиконазол, азоксистробин (R5, R8, R9, R10, R14, R17) |
| 2 | то же фото | 4 %, влажность 55 %, осадков не было | осмотр через 3 дня (R12 → R15) |
| 3 | фитофтороз картофеля | Картофель, 2 %, 18 °C, 90 %, ветер 7 м/с, 15 дней, FRAC 4 | отложить обработку, остаётся цимоксанил |
| 4 | бурая ржавчина пшеницы | культура «Картофель» | конфликт культуры, проверка (R2) |
| 5 | не лист | любой | переснять (R1) |
| 6 | здоровый лист | культура совпадает | обработка не требуется (R4) |

Все шесть сценариев проверены в запущенном приложении на фото из `examples/`: решения и правила совпали
(подробности и скриншоты — `results/README.md`, `results/screenshots/`). На реальном фото сценария 1
вероятность 0,996, цепочка CF: диагноз 1,00 → погода благоприятна 0,92 → риск высокий 0,90 → обработка 0,81.
Контрольный пример движка при вероятности 0,92: 0,92 → 0,88 → 0,83 → 0,75.

## Проверка качества

```bash
python evaluate.py                                   # модель из config.py
python evaluate.py ripro805/krishidrishti-plant-disease  # любая модель с Hugging Face
```

`evaluate.py` берёт снимки из `results/testset.csv` (сами файлы — в `data/`, в git не входят), прогоняет
нейросеть и всю систему с правилами и пишет в `results/<модель>/` accuracy, macro-F1, матрицу ошибок,
время и долю ошибок нейросети, которые перехватили правила. Итоги на 400 снимках, которых не было в
обучении модели: accuracy 55,5 % (автор модели заявляет 98 % на своей валидации), гибрид перехватывает 54 %
ошибок нейросети, «не лист» отсеян в 17 случаях из 17, распознавание — 14 мс на CPU. Подробно — `results/README.md`.

## Как добавить болезнь

1. В `kb/diseases.json` → `diseases` добавить запись: `id`, `crop`, `name_ru`, `pathogen`, `group`,
   `symptoms`, `threshold_min`, `threshold_max`, `threshold_note`, `t_min`, `t_max`, `rh_min`,
   `measures`, `products` (id из `products.json`), `note`, `demo`.
2. В `labels` добавить нормализованную метку модели (нижний регистр, `_` и `-` → пробел):
   `"wheat septoria": {"kind": "disease", "crop": "wheat", "disease": "wheat_septoria"}`.
3. Если нужны новые д.в. — добавить их в `kb/products.json`.

## Как добавить правило

Добавить объект в `kb/rules.json` → `rules`. Порядок важен: правила проверяются сверху вниз.

```json
{
  "id": "R21",
  "group": "Ограничения",
  "text": "ЕСЛИ решено обрабатывать И температура выше 25 °C ТО сообщить о рисках обработки в жару",
  "if": [
    {"fact": "action", "op": "==", "value": "treat"},
    {"fact": "temp", "op": ">", "value": 25}
  ],
  "then": [{"message": "Опрыскивать утром или вечером: днём {temp} °C"}],
  "cf": 1.0
}
```

Условия: `{"fact", "op", "value"}` или `{"fact", "op", "ref"}` (ref — имя другого факта);
операции `==`, `!=`, `<`, `<=`, `>`, `>=`, `in`, `not_in`, `exists`, `missing`; группа
`{"any": [...]}` — ИЛИ. Действия: `set`, `message`, `load_products`, `exclude_products`.
Изменения JSON применяются при следующем нажатии «Получить решение», без перезапуска.

## Ограничения

Учебный прототип. Часть порогов и сроков ожидания условные (`"demo": true`, в интерфейсе —
пометка «условные значения»). Перед применением пестицидов сверяйтесь с Государственным
каталогом пестицидов и агрохимикатов, разрешённых к применению на территории РФ.

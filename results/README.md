# Замеры: нейросеть и гибрид на открытых снимках

Все цифры ниже получены командой `python evaluate.py <модель>` 30.10.2026 на MacBook (CPU, без GPU).
Ничего не подставлено вручную: исходные ответы по каждому снимку лежат в `<модель>/predictions.csv`.

## Тестовые наборы (`testset.csv`)

| Набор | Снимков | Откуда | Есть ли в обучении модели |
|---|---|---|---|
| `test` — основной | 400 (10 классов × 40) | PlantDoc (картофель), AgML: кукуруза (Аньхой, Китай; Танзания; ЮАР), картофель (Индонезия), рис (Kaggle anshulm257), пшеница (Хэнань, Китай) | не найдено ни одного |
| `field` — полевые | 125 | DigiGreen/Crop_Disease_Images (фото фермеров, Индия) — 118, Wikimedia Commons — 7 | не найдено ни одного |
| `not_leaf` | 17 | случайные фото Wikimedia Commons | не найдено ни одного |
| `leak` — контроль утечки | 80 | PlantDoc-кукуруза (ржавчина, церкоспороз) | 61 точная копия, остальные — того же источника |

Классов «пшеница — здоровая» и «пшеница — жёлтая ржавчина» нет в `test`: открытых снимков вне обучающей
выборки нашлось мало (34 и 3), они вошли только в `field`.

**Как проверяли пересечение с обучением.** Автор модели выложил обучающий архив
[wambugu71/CropLeafDiseases](https://huggingface.co/datasets/wambugu71/CropLeafDiseases) (15 ГБ, 98 104 файла).
Мы прочитали его оглавление по HTTP Range, не скачивая архив целиком, и:
1. сравнили CRC32 и размер каждого тестового снимка со всеми 98 104 файлами (точные копии);
2. посчитали перцептивный хеш dHash (256 бит) для 5 554 обучающих снимков: всех снимков кукурузы не из
   PlantVillage, всех «image (N)» картофеля и по 40 подряд идущих снимков остальных классов — и нашли ближайший
   для каждого тестового. Дубли дают расстояние 0, разные снимки — 58 и больше; порог «есть в обучении» — 20.

Так выяснилось, что PlantDoc-кукуруза и 435 из 1519 снимков церкоспороза из `muAtarist/maize_foliar_diseases`
есть в обучении. Их убрали из `test`: для церкоспороза взяли 40 снимков без дублей, PlantDoc-кукурузу
вынесли в набор `leak`. Для риса и пшеницы dHash сравнивался только с выборкой обучающих снимков,
поэтому для них «не найдено» — это «точных копий нет и в выборке дублей нет», а не полная гарантия.

Сами снимки не публикуются (папка `data/` в `.gitignore`); в `testset.csv` указаны источник, номер строки
или файл и лицензия каждого снимка, так что набор можно собрать заново.

## Нейросеть: наша модель против альтернатив (`models_comparison.csv`)

| Модель | test, accuracy | test, macro-F1 | кукуруза + картофель (6 классов) | field, accuracy | «не лист» отсеяно | мс на фото |
|---|---|---|---|---|---|---|
| **wambugu71/crop_leaf_diseases_vit** (ViT-Tiny, наша) | **55,5 %** | **0,53** | **65,8 %** | **24,8 %** | **17 из 17** | **14** |
| ripro805/krishidrishti-plant-disease (ConvNeXt, 50 классов) | 51,0 % | 0,51 | 36,2 % | 16,8 % | 17 из 17 | 343 |
| rodynaemad/plant-disease-dinov2-small (PlantVillage) | 26,5 % | 0,27 | 44,2 % | 2,4 % | 10 из 17 | 35 |

- Автор нашей модели заявляет 98 % accuracy на своей валидации. На снимках, которых не было в обучении, мы
  получили **55,5 %**, а на снимках из обучения (набор `leak`) — **92,5 %**. Разрыв — это разница между
  «знакомыми» и новыми фото, а не ошибка замера.
- У krishidrishti рис распознаётся почти идеально (97–100 %), но наш рисовый тест (Kaggle anshulm257) есть в её
  обучающем списке (`reports/training_config.json` модели), поэтому эта цифра нечестная. Класса «бурая ржавчина
  пшеницы» у неё нет. На общих честных классах (кукуруза, картофель) она хуже: 36,2 % против 65,8 %.
- `shehryars715/crop_leaf_diseases_vit` и `cabrel09/crop_leaf_disease_detector` оказались байт-в-байт копиями нашей
  модели (одинаковый SHA-256 весов), поэтому их не сравнивали.
- Резервная модель из `config.py` (`linkanjarad/mobilenet_v2…`) не загружается в transformers 5.x: в её
  `preprocessor_config.json` нет `image_processor_type`.
- **Вывод: остаёмся на wambugu71/crop_leaf_diseases_vit** — она лучшая из проверенных и самая быстрая.

## Польза гибрида

Для каждого снимка с известным ответом запускается вся система: нейросеть, затем правила с условиями
сценария 1 (6 %, 20 °C, 85 %, осадки были), а культура на поле — истинная, как её указал бы агроном.
«Ошибка нейросети» — она назвала **не ту болезнь**, то есть без правил была бы рекомендована неверная обработка.
«Перехвачена» — система вместо обработки ответила «перепроверить» или «переснять».

| | test (400) | field (125) |
|---|---|---|
| Нейросеть назвала не ту болезнь | 126 (31,5 %) | 25 (20,0 %) |
| Гибрид перехватил | **68 из 126 (54 %)** | **17 из 25 (68 %)** |
| — правилом R2 (культура на фото ≠ культура на поле) | 29 | 12 |
| — правилом R3 (вероятность < 0,60) | 39 | 5 |
| Ошибка всё равно дошла до рекомендации | 58 (14,5 % всех снимков) | 8 (6,4 %) |
| — из них со статусом «вероятен», с предупреждением «сверьте признаки» (R6) | 29 | 3 |
| Цена: верный ответ, но система попросила перепроверить | 24 из 222 (10,8 %) | 10 из 31 |
| «Не лист» отсеян (R1) | 17 из 17 | — |

Итог: **гибрид перехватывает 54 % ошибок нейросети** на основном наборе (68 % на полевых фото), и доля неверных
рекомендаций падает с 31,5 % до 14,5 %. Чего правила не ловят: 97 из 126 ошибок — путаница болезней **одной
культуры** (фитофтороз ↔ альтернариоз, бурая пятнистость ↔ пирикуляриоз). Их видно только по уверенности
нейросети, а модель часто ошибается уверенно.

Среднее время распознавания одного фото — 14 мс на CPU, максимум 82 мс (по ТЗ — не больше 2 с).

## Файлы

- `testset.csv` — список снимков, источники, лицензии, проверка на пересечение с обучением;
- `<модель>/predictions.csv` — ответ модели и решение системы по каждому снимку;
- `<модель>/metrics.json` — accuracy, macro-F1, точность по классам, польза гибрида, «не лист», время;
- `<модель>/confusion.csv` — матрица ошибок на `test`;
- `models_comparison.csv` — сводная таблица моделей;
- `screenshots/` — экраны интерфейса для сценариев 1–6 и погоды.
